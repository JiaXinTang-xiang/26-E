本文对应当前工程：

- 上位机：`C:\Users\JXT\Desktop\拼图\puzzle-vision-simulator`
- 下位机：`C:\Users\JXT\Desktop\拼图\TicTacToe_Demo - 202512`

## 2. 推荐完整操作顺序

第一次安装或相机、龙门架位置发生变化时：

1. 烧录最新下位机程序。
2. 测试 CH340 和 STM32 双向通信。
3. 标定像素坐标到 XY 脉冲坐标。
4. 框选 A4 ROI，采集空白橙黄色 A4 背景。
5. 调好并保存碎片识别参数。
6. 锁定识别结果并计算拼接方案。
7. 先单块执行，再自动连续执行全部碎片。

平时比赛前，如果相机、A4 纸和龙门架均未移动，可以直接：

1. 启动正式控制界面。
2. 选择本轮碎片数。
3. 一键识别并计算方案。
4. 先发送当前块检查，再自动连续执行。

在 Keil 中执行：

3. 确认结果为 `0 Error(s), 0 Warning(s)`。
4. 连接下载器。
5. 点击 `Download` 烧录。
6. 按下 STM32 复位键，等待电机初始化和回零完成。

当前固件通信状态：

| 状态 | 含义 | 上位机处理 |
|---|---|---|
| `B0` | 命令校验通过并开始执行 | 显示“正在执行” |
| `B1` | 当前取放动作完成并已回零 | 单块等待确认，自动模式发送下一块 |
| `B2` | 帧校验失败或坐标/角度越界 | 拒绝任务，不执行动作 |
| `B3` | 正常 XY/Z 运动中，脉冲计数连续约 1 秒不变化 | 停止三轴、关闭电磁铁、停止自动任务 |

说明：`B3` 的计数检测只用于正常 XY/Z 运动，没有修改限位开关和 `ResetStepMotor()` 回零逻辑。

## 4. 串口诊断命令

### 4.1 CH340 自环测试

用途：只验证 CH340 的 TXD 和 RXD，不连接 STM32。

接线：

1. 断开 CH340 与 STM32 的 TX/RX。
2. 短接 CH340 的 `TXD` 和 `RXD`。
3. 执行：

```powershell
python -m tools.serial_return_test --serial COM30 --loopback
```

正常结果：

```text
PASS: CH340 TXD/RXD loopback is working.
```

测试完成后必须拆除 TXD/RXD 短接，再恢复与 STM32 的接线。

可选参数：

- `--serial COM30`：CH340 端口，必须填写。
- `--baudrate 115200`：波特率，默认 `115200`。
- `--timeout 2`：等待秒数，默认 `2` 秒。
- `--loopback`：启用 CH340 自环模式。

### 4.2 STM32 返回通道测试

用途：发送一个故意损坏校验值的安全帧，STM32 应返回 `B2`。该帧在使用坐标前就会被拒绝，不会启动电机。

接线：

- STM32 `PA9 / USART1_TX` -> CH340 `RXD`
- STM32 `PA10 / USART1_RX` <- CH340 `TXD`
- STM32 GND 与 CH340 GND 共地

执行：

```powershell
python -m tools.serial_return_test --serial COM30 --timeout 5
```

正常结果：

```text
RX 5 B: AA 03 B2 B1 55
PASS: STM32 TX -> CH340 RX -> PC return path is working.
```

若显示 `RX 0 B`，依次检查：

1. 端口号是否正确。
2. 是否有其他上位机窗口占用 COM 口。
3. PA9 是否接 CH340 RXD。
4. PA10 是否接 CH340 TXD。
5. 是否共地。
6. 下位机是否重新烧录了最新固件。

### 4.3 STM32 上电监听测试

```powershell
python -m tools.serial_listen_test --serial COM30 --timeout 12
```

程序提示监听后，按下 STM32 复位键或重新上电。如果当前烧录的固件保留上电诊断帧，应收到：

```text
AA 03 BD BE 55
```

如果当前正式固件未发送该诊断帧，本测试可能不会通过；此时优先使用上一节的 `serial_return_test` 验证正式双向通信。

## 5. 相机到龙门架标定

### 5.1 启动命令

```powershell
python -m apps.manual_calibration_gui --camera 1 --serial COM30
```

参数：

- `--camera 1`：USB 相机编号。
- `--serial COM30`：CH340 端口；不填写时可以记录点，但不能发送真实动作。
- `--no-rotate-180`：关闭默认的 180° 旋转。当前设备不要添加这个参数，否则会与已经保存的 ROI 和标定方向不一致。

### 5.2 标定点的含义

- 像素点：在相机画面中点击的吸头中心位置。
- 脉冲点：吸头此时相对于回零点的绝对 X/Y 脉冲坐标。
- 源点和目标点只是一次标定任务内的两组位置，两者都可以作为标定样本。

不是“点击鼠标后让程序猜脉冲值”，而是：已知机械移动到了哪个脉冲位置，再点击画面中对应的吸头中心，保存一组“像素 -> 脉冲”。

### 5.3 每组标定操作

1. 等待下位机完成初始化和回零。
2. 在界面填写源取棋脉冲 `X/Y` 和目标放棋脉冲 `X/Y`。
3. 点击“锁定本次两组脉冲”。
4. 使用现有动作或手动控制，让吸头到达源脉冲位置并完全停稳。
5. 点击“准备记录源点”，再点击画面中的吸头实际中心。
6. 让吸头到达目标脉冲位置并完全停稳。
7. 点击“准备记录目标点”，再点击画面中的吸头实际中心。
8. 更换下一组脉冲位置，重复以上步骤。

“发送旧取放帧”会执行真实取放和回零，只在已经确认机械安全时使用。若下位机不会在源点和目标点停留足够长，应由人工控制到位后再点击记录。

### 5.4 点位数量和分布

代码最少使用 3 个不共线点即可拟合稳定平均矩阵，但实机不要只标 3 个点。推荐：

- 至少 `12~16` 个点。
- 覆盖 A4 识别区四角、四边和中央。
- 不要把所有点集中在一小块区域。
- 吸头必须处于和实际抓取一致的高度。
- 鼠标点偏的样本应选中后删除。

### 5.5 拟合、保存和测试

1. 点击“拟合稳定平均矩阵”。
2. 查看平均误差和最大误差。
3. 删除明显点错的样本后重新拟合。
4. 点击“保存到 `configs/local/calibration.json`”。
5. 在“矩阵取放测试”中分别选择画面取棋点和放棋点。
6. 检查界面换算出的脉冲没有超出 X/Y 范围。
7. 点击“确定：执行取棋、放棋、回零”进行实机验证。

标定文件：

- 草稿点：`configs/local/calibration_points_draft.json`
- 正式矩阵：`configs/local/calibration.json`
- 可选临时矩阵：`configs/local/calibration_temporary.json`

只要相机位置、焦距、分辨率、180° 方向、A4 位置或龙门架零点关系发生变化，就要重新标定。

## 6. 碎片识别和 ROI 调试

### 6.1 启动主识别界面

```powershell
python -m apps.piece_detection_gui --camera 1
```

该界面只做视觉识别和方案计算，不发送电机命令。

### 6.2 首次设置 A4 ROI

1. 保证相机画面方向正确，默认已旋转 180°。
2. 点击“框选 A4 ROI”。
3. 在主画面中从 A4 左上角拖到右下角。
4. ROI 应完整覆盖橙黄色 A4 工作纸。
5. 上半区用于放置和识别原始碎片，下半区用于生成拼接目标。

保存位置：`configs/local/a4_roi.json`。

如果重新框选 ROI，背景图也应重新采集。

### 6.3 采集空背景

1. 移走所有白色碎片和吸头。
2. 保留空的橙黄色 A4 纸。
3. 点击“采集当前空桌面为背景”。

保存位置：`data/local/empty_work_area.png`。

当前推荐使用背景差分。背景采集后不要移动相机、A4 纸或改变灯光；发生变化时重新采集。

### 6.4 参数调整顺序

不要一次同时修改所有参数。推荐顺序：

1. 先选“背景差分”。
2. 调分割阈值，让白色碎片区域为白色，橙色纸为黑色。
3. 调最小面积，滤除小噪点。
4. 调最大面积，滤除大片错误区域；填 `0` 表示禁用最大面积限制。
5. 调形态学尺寸，填补小孔、清除小噪声。
6. 调高斯模糊，降低毛刺；数值必须是合适的奇数。
7. 调 Canny 上下阈值观察外轮廓。
8. 调多边形 epsilon，控制轮廓简化后的顶点数。
9. 调最小/最大顶点数，保留真实碎片轮廓。
10. 调安全抓取间隙，保证吸头中心远离碎片边缘。

参数含义：

| 参数 | 作用 | 调整现象 |
|---|---|---|
| 分割方法 | 背景差分、白色 HSV 或亮度阈值 | 当前橙纸+白片优先背景差分 |
| 最小面积 | 去掉小噪点 | 噪点多就增大；小碎片消失就减小 |
| 最大面积 | 去掉大块误识别 | A4 或大片反光被框出时减小 |
| 颜色差阈值 | 当前画面和空背景的 Lab 色差门限 | 碎片缺失时降低；背景噪声多时提高 |
| 白色 S 最大值 | 白色允许的最大饱和度 | 只对白色 HSV 模式有效 |
| 白色 V 最小值 | 白色允许的最低亮度 | 白片偏暗时降低 |
| 亮度最小值 | 亮度分割门限 | 只对亮度模式有效 |
| 形态学尺寸 | 去噪、补洞 | 轮廓破碎可稍增；相邻碎片粘连则减小 |
| 高斯模糊 | 平滑图像 | 毛刺多时稍增，细节丢失时减小 |
| Canny 下/上阈值 | 边缘显示 | 边缘太少就降低，噪声边太多就提高 |
| epsilon 最小/推荐/最大 | 多边形轮廓简化程度 | 顶点太多时提高，顶点太少时降低 |
| 最小/最大顶点 | 合法碎片顶点范围 | 当前默认适合 3~5 顶点轮廓 |
| 最小抓取间隙 | 抓取点到边缘的安全距离 | 吸头太靠边时提高，找不到抓取点时降低 |

参数改变后，画面需要重新分析并重新稳定采样。调好后点击“保存参数”。

保存位置：`configs/local/vision_detection.json`。

“恢复上次保存”会恢复这个文件中的参数，不是恢复出厂默认值。

### 6.5 稳定锁定和计算方案

1. 确认每块碎片都具有轮廓、顶点、中心、方向和安全抓取点。
2. 保持碎片和相机静止，等待“稳定，可确认锁定”。
3. 点击“确认并锁定”。
4. 点击“计算拼接方案”。
5. 检查下半区绿色拼接预览，确认碎片无重叠、整体形状正确。

输出文件：

- 锁定识别：`output/locked_piece_observations.json`
- 拼接方案：`output/assembly_plan.json`
- 拼接预览：`output/assembly_preview.png`

如果参数或碎片发生变化，点击“解除锁定，重新采样”，然后重新锁定和计算。

如果需要单独看差分、白色掩膜、亮度掩膜、边缘和最终掩膜：

## 7. 正式拼接控制界面

### 7.0 比赛一键界面（推荐）

```powershell
python -m apps.competition_gui --camera 1 --serial COM30
```

比赛页采用两行两列的固定题目卡片，不需要上下滚动：

- `1（1）自备4块只搬运`：固定等待4块稳定识别，保持每块原方向，放到A4下半区4个固定纸面位置，不调用拼接解算。
- `1（2）自备4块拼接`：固定等待4块，优先完整边和原来的约100×60 mm、5:3矩形规则。若没有可靠拼接方案，不会直接放弃本题，而是自动降级为4块固定区域搬运，尽量保证仍能取得搬运分。
- `2（1）现场白色碎片`：自动判断1～4块，动态恢复目标矩形尺寸，然后自动执行。
- `2（2）扑克牌碎片`：自动判断1～4块，先筛选尺寸、矩形度、凸度和重叠率均合格的几何方案，再比较各条拼接缝两侧的牌面颜色连续性，选择花纹断裂最小的方案并自动执行。

扑克牌模式不依赖固定牌面模板，因此更换点数或花色后无需重新制作模板。相机画面应避免强反光和运动模糊；预览中的 `texture seam` 以及方案文件中的 `quality.texture_score` 都是“越低越连续”，每条接缝的分数记录在 `quality.texture_seam_scores`。

按下已实现的题目按钮后立即开始120秒计时。方案通过脉冲和角度校验后，程序不再弹出人工确认框，自动发送第一块，并且每块只在收到本次 `B1` 后才发送下一块。全部完成后计时冻结，界面变为绿色并发出三次电脑提示音。

每一轮完成、失败或停止后，可以直接再次点击任意题目按钮，也可以点击“再次运行上一题”。程序会清除旧任务、旧预览、旧串口解析缓存和旧计时，但保留相机、ROI、背景、视觉参数和标定矩阵，不需要退出并重新运行Python。

如果刚做过调试计算、上一次比赛异常退出，或界面看起来还保留旧任务，可先点击“刷新当前状态”。它会清除比赛任务、预览、计时、未完成的视觉计算和串口接收缓存，但不会关闭相机、断开串口、修改ROI、视觉参数或标定矩阵。机械动作尚未收到完成状态时，刷新按钮会拒绝执行，避免上位机丢失下位机正在执行的状态。

`停止后续任务` 只能停止尚未发送的碎片，不能急停已经发送给下位机的当前块。真正紧急情况仍需切断电机动力。

调试页保留：

- 自动判断1～4块并只计算方案。
- 固定4块并只计算方案。
- 单块或连续运动测试（保留安全确认框）。
- 舵机方向切换、串口重连和解除上位机等待。
- 安全通信自检：发送故意校验错误的帧，收到 `B2` 表示双向串口正常，该帧不会启动电机。
- 重启上位机串口：只关闭并重新打开 CH340，不会复位 STM32，也不会重发当前碎片。
- 刷新并自动查找 CH340：USB 重插造成 COM 号改变时自动更新端口；若同时有多个 CH340，则要求手工选择，避免连错设备。
- 打开视觉调参、像素脉冲标定和OpenCV分阶段调试工具。
- “背景颜色调试（橙色A4 / 白色碎片）”会打开独立OpenCV滑块窗口，可同时观察背景差分、白色HSV、亮度阈值和最终掩膜；该工具不连接串口，也不会移动电机。

每轮比赛日志保存在：

```text
output/competition_runs/
```

串口恢复策略：

- 空闲、识别和拼接计算阶段掉线：按 `0.5/1/2/3/5` 秒退避自动重连，之后每5秒继续尝试。
- 自动重连时会先检查原 COM 号；若原端口消失且系统中只有一个 CH340，会自动切换到新的 COM 号。
- 已经发送机械动作后掉线：立即停止后续自动任务，允许恢复 PC/Jetson 串口句柄，但不自动重发当前块，避免同一块执行两次。
- 动作期间掉线后，应先观察机械是否完成并回零，再使用调试页“确认当前块已完成并回零”或“解除上位机等待”。
- “重启上位机串口”不能代替 STM32 硬件复位；若下位机程序确实卡死，需要按板上的复位键，等待电机重新初始化回零后再继续。

```bash
chmod +x 启动比赛.sh 启动标定.sh
./启动比赛.sh
```

程序现在会按源码目录寻找 `configs/`、`data/` 和 `output/`，不要求必须从工程目录启动。
部署时必须保留 `configs/local/a4_roi.json`、`configs/local/calibration.json`、
`configs/local/vision_detection.json` 和 `data/local/empty_work_area.png`。

Jetson Nano 不建议直接用 pip 安装 ARM 版 OpenCV。优先使用 JetPack 自带的
`python3-opencv`、`python3-numpy`，再执行 `pip3 install -r requirements-jetson.txt`。

参数：

- `--camera 1`：USB 相机编号，默认值也是 `1`。
- `--serial COM30`：CH340 串口号。
- `--no-rotate-180`：使用原始方向；当前设备不要添加。

### 7.2 启动后的检查

1. 等待下位机初始化和回零完成。
2. 检查相机画面方向、ROI 和碎片区域。
3. 检查串口框中的端口是否正确，点击“连接”。
4. 确认状态显示 `COMxx @ 115200`。
5. 选择本轮真实碎片数量 `1/2/3/4`。
6. 选择舵机旋转方向。若实际旋转与规划方向相反，切换“同向/反向”后重新加载或重新计算方案。

### 7.3 一键识别并计算方案

点击“一键重新识别并计算拼接方案”。程序会：

1. 读取已保存的视觉参数、A4 ROI、空背景和标定矩阵。
2. 等待所选数量的碎片稳定。
3. 识别轮廓、安全抓取点和方向。
4. 计算目标位置、取料角度、放料角度和 5 mm 安全间隙。
5. 保存并自动加载最新拼接方案。

成功后应看到：

- 下半区绿色拼接预览。
- 任务列表出现 P0、P1 等任务。
- 每项显示源 XY、目标 XY、相对旋转角、抓取角和放置角。

如果失败，会保存诊断文件：

- `output/assembly_plan_failed.json`
- `output/assembly_preview_failed.png`

### 7.4 单块执行

首次实机测试必须先用单块模式：

1. 点击“发送当前块（每次仅一块）”。
2. 检查确认框中的取点、放点和两个舵机角度。
3. 确认机械安全后允许发送。
4. 通信日志应依次出现：

```text
TX P0: ...
STATUS B0: 命令已接收
STATUS B1: 动作已完成并回零
```

5. 肉眼确认碎片已放好、Z 轴抬起、XY 回零、舵机回到 `135°`。
6. 点击“确认当前块已完成并回零”，任务才会推进到下一块。

当前下位机单块动作顺序：

1. XY 移动到取料点。
2. 舵机转到计算出的抓取角。
3. Z 下降，电磁铁吸取碎片。
4. Z 抬升。
5. XY 移动到目标点。
6. 舵机转到计算出的放置角。
7. Z 下降，电磁铁释放碎片。
8. Z 抬升。
9. 舵机回 `135°`。
10. XY 回零并返回 `B1`。

### 7.5 自动连续执行全部

单块验证无误后：

1. 确认任务列表、碎片位置和拼接预览正确。
2. 点击“自动连续执行全部”。
3. 确认安全提示。
4. 程序每次只发送一块，必须收到本次 `B0` 后才接受 `B1/B3`。
5. 收到 `B1` 后约 500 ms 才发送下一块。

正常日志：

```text
TX P0
RX B0
RX B1
TX P1
RX B0
RX B1
...
```

“停止自动执行（当前块不打断）”只停止后续碎片，当前已经发送的动作会继续完成。

### 7.6 取消发送状态

“取消本次发送状态（不推进）”只解除上位机等待状态：

- 不会停止正在运动的下位机。
- 不会把当前块标记为完成。
- 不会发送任何新命令。

只有在确认机械状态明确、自动模式已经停止时使用。如果机械动作状态未知，应先断开动力并人工检查，不要立即重复发送。

## 8. 常见问题

### 8.1 `No module named 'apps'`

原因：终端不在工程根目录。

```powershell
cd "C:\Users\JXT\Desktop\拼图\puzzle-vision-simulator"
```

然后重新执行命令。

### 8.2 COM 口找不到或无法连接

1. 用 PowerShell重新列出端口。
2. 关闭其他占用 COM 口的 Python 界面、串口助手或 Keil 串口工具。
3. 重新插拔 CH340。
4. 更新命令中的 `--serial COMxx`。

### 8.3 相机打不开或画面卡住

1. 关闭所有其他使用该 USB 相机的程序。
2. 确认相机编号。
3. 拔插相机后重启界面。
4. 不要同时运行识别界面和正式控制界面占用同一相机。

### 8.4 改参数后画面看起来没变化

1. 确认参数输入合法。
2. 等待当前分析帧完成。
3. 观察“掩膜”和“外边缘”窗口，不要只看原图。
4. 如果当前结果已经锁定，先“解除锁定，重新采样”。

### 8.5 拼接方案未找到

检查：

1. 所选碎片数量是否等于实际识别数量。
2. 每块是否形成独立完整轮廓。
3. ROI 是否正确覆盖 A4。
4. 背景是否在无碎片时采集。
5. 是否等待稳定并锁定。
6. `output/assembly_plan_failed.json` 中的矩形填充率、凸度、重叠率等诊断信息。

### 8.6 P0 或其他任务脉冲越界

允许范围为：

```text
X: 0~2350
Y: 0~1350
```

出现负值或超上限，通常不是拼接间隙本身造成，而是：

- 碎片或目标点太靠机械范围边缘。
- 标定点覆盖不足或点击误差大。
- 相机、A4 或龙门架位置改变后没有重新标定。

不要简单截断负数为 0。应移动碎片、调整工作区或重新标定后再计算。

### 8.7 收到 `B0` 后机械不动

最新固件会监测正常 XY/Z 脉冲计数：任一仍有剩余脉冲的轴连续约 1 秒计数不变化，就停止三轴、关闭电磁铁并返回 `B3`。

收到 `B3` 后：

1. 自动连续执行会停止。
2. 不要直接重发。
3. 检查对应定时器、中断、驱动使能、电机电源和接线。
4. 人工确认机械位置，再决定是否复位和重新执行。

### 8.8 一次动作像执行了两次

先看通信日志。正常自动模式中，上一块回零并收到 `B1` 后发送下一块是预期行为。

正确顺序必须是：

```text
TX P0 -> B0 -> B1 -> TX P1
```

当前上位机会在发送新任务前清除旧串口状态，并且只有本次先收到 `B0`，才接受后续 `B1/B3`。下位机也会在开始处理前消费当前接收标志，避免同一帧重复执行。

正常流程中的蜂鸣器位于回零末尾，每块完成会响一次。4 块自动执行通常会响 4 次。若同一块明显响两次，检查日志是否真的出现了第二条 `TX P...`，以及 STM32 是否意外复位。

## 9. 其他调试命令

### 9.1 单张图片识别

```powershell
python -m puzzle_device.vision.piece_vision "data\test.png" --config "configs\local\vision_detection.json" --output "output\piece_detection"
```

带空背景和 ROI：

```powershell
python -m puzzle_device.vision.piece_vision "data\test.png" --background "data\local\empty_work_area.png" --roi 100,50,900,650 --output "output\piece_detection"
```

主要参数：

- 第一个位置参数：输入图片。
- `--background`：空工作区背景图。
- `--output`：输出目录。
- `--roi X,Y,W,H`：输入图中的裁剪区域。
- `--min-area`：最小轮廓面积，默认 `800`。
- `--max-area`：最大面积，`0` 表示不限制。
- `--threshold`：固定 Lab 色差阈值。
- `--config`：视觉参数 JSON。

输出包括：

- `mask.png`
- `detected.png`
- `pieces.json`

### 9.2 算法仿真

运行一次 4 块仿真：

```powershell
python -m puzzle_device.simulation.puzzle_sim --pieces 4 --seed 7 --output output\demo
```

批量验证 100 次：

```powershell
python -m puzzle_device.simulation.puzzle_sim --pieces 4 --seed 1 --batch 100
```

参数：

- `--pieces 2|3|4`：仿真碎片数量。
- `--seed`：随机种子，相同种子可以复现相同案例。
- `--output`：输出目录。
- `--batch`：批量运行次数；大于 0 时主要输出统计结果。

启动旧的 Tk 算法仿真界面：

```powershell
python -m apps.puzzle_gui
```

这些仿真命令不连接真实下位机。

全部自动测试：
